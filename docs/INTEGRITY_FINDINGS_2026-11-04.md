## F1 — The Phase 39 / Phase 40 "SIDM" rotation curve never sees σ/m  (MEASURED, DISCLOSED)

**Claim in the code.** `phase39_nfw_vs_sidm.py` and `phase40_corrected_comparison.py`
documented a "velocity-dependent core radius (Kaplinghat+ 2016)":
`r_core = 0.45 * r_s * (sigma_kpc * rho_s * r_s / v_max_natural)**0.25`, clamped to
`[0.1 r_s, 10 r_s]`.

**What was measured.** Probes run with `.venv-sidm-bench/Scripts/python.exe` against the
real functions (not a reimplementation):

| probe | result |
|---|---|
| `v_circ_sidm_multi_resonant` with σ₀ = 1e-6, 1e-3, 0.195, 10, 1e3, 1e5 cm²/g | max abs difference between curves **exactly 0.0** |
| all four resonance peak heights set to 0 | max abs difference **0.0** |
| velocity slope `a_slope` = 0, 0.7, 3.0 | max abs difference **0.0** |
| `phase40.v_circ_sidm`, same σ scan | max abs difference **0.0** |
| raw `r_core` over the full fit grid the scripts search (210 points: log ρ_s ∈ 4…9, log r_s ∈ −0.5…2.0, V_max ∈ 35…260 km/s) | **210/210 below the 0.1·r_s floor**; worst case reaches only **0.111** of the floor |

**Why.** Two independent defects in one expression:
1. `v_max_natural = v_max_kms * 3.086e16 / 3.156e10` is labelled "km/s → kpc/Gyr" but the
   correct factor is `1/0.9778 = 1.0227`. The code's factor is **9.56e5× too large**.
2. `sigma_kpc * rho_s * r_s` is already **dimensionless** (kpc² M☉⁻¹ × M☉ kpc⁻³ × kpc), so
   dividing it by a velocity is dimensionally inconsistent.

Net effect: raw `r_core` is 2–4 orders of magnitude below its own floor, the clamp fires
everywhere, and σ/m, the resonance spectrum and the velocity slope are all removed from
the model before they reach the fit.

**Consequence for the certified headline.** Stored `phase39_nfw_vs_sidm.json` records
log L(NFW) = −1509.6498, log L(SIDM) = −1205.1409, Δ = **+304.51** over 15 galaxies,
verdict **STRONG_SIDM**. That Δ is *not* a SIDM result: it says "a cored profile with a
fixed core radius of 0.1·r_s fits these galaxies better than an NFW cusp". The multi-resonant
particle model contributes nothing to it. The stored caveat calls the profile "simplified";
the measured truth is stronger — it is **σ/m-independent**.

**What was done.** The arithmetic was **not** changed (choosing a replacement profile is a
physics decision, see D1). Instead:
- the defect is documented in both module docstrings and inline at the expression;
- `v0.3-prelim/tests/test_sidm_core_radius_invariance.py` now **pins** the invariance. If
  anyone repairs the core radius, that test fails on purpose, forcing a re-derivation of
  phase39/phase40 and an update of this file.

## F2 — Velocity unit mismatch in the rotation-curve fits  (FIXED)

`v_circ_*` used `G = 4.5e-6 kpc³ M☉⁻¹ Gyr⁻²`, which yields speeds in **kpc/Gyr**, and the
χ² routines compared those numbers directly with SPARC `Vobs_kms` / `eV_kms`, which are
**km/s**. Measured on a real SPARC rotmod file (9 data points): the ratio
`V(with 4.5e-6) / V(with 4.302e-6)` = **1.022754, identical at every radius** — i.e. every
modelled dark-matter velocity was inflated by **2.28%**, which a free density absorbs as
roughly a **−4.55%** shift. `config.py:111` already shipped the correct constant.

**Fix applied.** Both modules now use `G_KPC_KMS = 4.302e-6 kpc (km/s)² M☉⁻¹` (module-level
`G_KPC_KMS`, all three `G = 4.5e-6` assignments per file replaced).

**Verification.** `test_sidm_core_radius_invariance.py::test_phase39_nfw_velocity_matches_si`,
`test_phase39_burkert_velocity_matches_si`, `test_phase40_nfw_velocity_matches_si` recompute
the same circular velocities from scratch in SI (`G = 6.67430e-11 m³ kg⁻¹ s⁻²`,
`M☉ = 1.988475e30 kg`, `1 kpc = 3.0856775814913673e19 m`, Burkert by `scipy.integrate.quad`)
and agree with the module output to better than 2×10⁻³ relative. A static check asserts that
neither module reassigns `G = 4.5e-6`. Run: 21 passed.

**Artifact bookkeeping.** Pre-fix artifacts preserved byte-identically (sha256
`d4ce811328e6…` verified equal before copying) under
`v0.3-prelim/data/results/superseded/` with `.pre_unitfix_2026-09-27` suffixes; the live
`phase39_nfw_vs_sidm.json` and `phase40_corrected_comparison.json` were regenerated by the
corrected code (15 and 120 galaxies, same seeds).

**What the unit fix did to Phase 39** (the test the STRONG_SIDM label rests on):

| quantity | pre-fix | re-derived |
|---|---|---|
| log L NFW | −1509.6498 | **−1538.9531** |
| log L SIDM (cored) | −1205.1409 | **−1205.1408** |
| Δ log L (SIDM − NFW) | +304.5089 | **+333.8123** |
| ΔAIC / ΔBIC (NFW − SIDM) | 609.0177 | **667.6246** |
| verdict | STRONG_SIDM | STRONG_SIDM |

The cored model barely moved (−0.0001) while NFW moved by 29.3 log units: the unit error was
absorbed differently by the two profile families, which is why fixing it widens a gap that
had been quoted in the docs as +304.

## F3 — Phase 40 contradicts itself inside one artifact  (MEASURED, OPEN)

Stored `phase40_corrected_comparison.json` (120 galaxies) contains both of these:

- Occam/AIC block: `aic_diff_phys_nfw_minus_sidm = −306.01`,
  `aic_diff_phys_burk_minus_sidm = −2210.82` → after the physical-parameter penalty,
  **NFW and Burkert are preferred**.
- `verdicts`: `fit_nfw_vs_sidm`, `fit_burk_vs_sidm`, `phys_nfw_vs_sidm`, `phys_burk_vs_sidm`
  are **all** labelled `STRONG_SIDM`.

**Why the labels disagree.** `delta_phys = delta_fit − (k_phys_sidm − k_phys_nfw) * 2`
subtracts a penalty of 20 from a **sum** of Δ log L over 120 galaxies (+1047.00). Against a
summed quantity the per-model penalty is negligible, so the label never changes. The AIC
path (which penalises per model) reaches the opposite conclusion. The two answers are not
"two views of the same thing" — one of them is misapplied statistics.

**Sample sensitivity, same artifact.** totals: SIDM − NFW **+1047.00**, SIDM − Burkert
**+94.59**; medians per galaxy: SIDM − NFW **+1.40**, SIDM − Burkert **−0.15**. The per-galaxy
median says SIDM is *slightly worse than Burkert*; the total is dominated by a few outliers
(the file itself names UGC 02916 as the dominant one).

**Measured again after the F2 unit fix** (same code path, same 120 galaxies, same seed):

| quantity | pre-fix artifact | re-derived 2026-11-04 |
|---|---|---|
| log L NFW | −4033.2132 | **−4260.3686** |
| log L Burkert | −3080.8036 | **−3008.3634** |
| log L SIDM | −2986.2161 | **−2991.8975** |
| Δ SIDM − NFW (total) | +1046.9971 | **+1268.4711** |
| Δ SIDM − Burkert (total) | +94.5875 | **+16.4659** |
| Δ SIDM − Burkert (median) | −0.1530 | **−0.1548** |
| `aic_diff_phys_nfw_minus_sidm` | −306.0059 (NFW better) | **+136.9422 (SIDM better)** |
| `aic_diff_phys_burk_minus_sidm` | −2210.8250 | **−2367.0682** |
| verdict `phys_burk_vs_sidm` | STRONG_SIDM | **WEAK_BURKERT** |

The physical-AIC sign flipped. A 2.3% velocity fix should not overturn a model-comparison
conclusion — the fact that it does shows the scoring is dominated by bookkeeping.

**The bookkeeping itself is inconsistent, in two incompatible ways.**
- `delta_phys = delta_fit − (k_phys_sidm − k_phys_nfw) * 2` subtracts a penalty of 20 once
  from a Δ log L **summed over 120 galaxies**, so the penalty is ~1.6% of the quantity it is
  meant to discipline and the verdict label never changes.
- `aic_*_phys` sums `2·k_phys` **per galaxy**, charging the 10 extra SIDM particle parameters
  120 times (2400 AIC units) even though those parameters are shared by every galaxy and are
  not re-fitted per galaxy.
Whichever convention is chosen decides the published verdict; the data do not.

**Not fixed here.** Re-scoring model comparison (per-model versus per-dataset penalties, and
how UGC 02916-type outliers enter) changes published verdicts. Decision D2.

## F4 — Direct-detection unit constant is ~1.78× off, in a channel that IS in the canonical fit  (MEASURED, DISCLOSED)

`channels_extended.py:239` (and the identical copy at `:320`, in
`loglike_competitor_dd_watch`) convert σ/m to a per-nucleon cross section with
`sigma_m * 1e-24 * m_chi_GeV`. Using 1 GeV = 1.783e-24 g, the constant is ~1.78× small,
so the channel overstates safety margins below ~0.75 GeV dark matter.

`loglike_direct_detection_exclusion` **is** summed in the canonical fit
(`t41_mediator_mass_joint_fit.py`, weights 0.5). The correction is therefore *not* a
cosmetic patch — it changes certified posterior numbers — so the constant was left in
place and documented in both docstrings. Decision D3.

## F10 — `gravothermal_yang2024.rho_sidm` was inverted relative to its cited equation  (FIXED 2026-11-04, D7 closed)

**Measured.** The module computes `rho_s * [(r^b+r_c^b)/(r_s^b+r_c^b)]^(1/b) * (r_s/(r+r_s))^2`.
arXiv:2305.16176 eq. 2.1 is `rho_s / [ ((r^b+r_c^b)^(1/b)/r_s) * (1+r/r_s)^2 ]`. Their ratio at
`r_c = 0` is exactly `(r/r_s)^2`, so the module does **not** reduce to NFW when the core vanishes.
At `rho_s = 1e7`, `r_s = 3 kpc`: 0.028× NFW at 0.5 kpc, 1.0× at 3 kpc, 11.1× at 10 kpc, 100.0× at

biases N **downward** toward "mild". So the current "no fine-tuning problem" reading is an
artifact of the sampling, not evidence. The archived "extreme" reading is evidence from a run
that is no longer reproducible from the repo.

**Fix applied (no physics retuned):**

- The producer now reads run quality from the artifact and publishes `run_quality` (nlive,
  n_samples, ndim, wall_seconds, wimpy_available, channels satisfied, `degraded_run`,
  `degraded_reasons`, thresholds `nlive_min=500`, `samples_min=2000`) and a `verdict_scope`
  string stating the verdicts are not supportable while degraded.
- The framework label now comes from the artifact instead of being hard-coded.
- `analyze_t41_v08()` got the same treatment in the passing direction: its `nlive=2000` claim
  is checked against the artifact's own `t41_version.nlive` (verified 2000, dlogz 0.1, ndim 6),
  so a T41 claim cannot drift out of sync with its chain silently.
- `v0.3-prelim/tests/test_t90_v60_naturalness.py`: the `mu_x_extreme` and `m_chi_severe` tests
  were retargeted to pin the measured values, require `degraded_run=True`, and pin the
  downward-bias direction. Two new tests pin the artifact-derived label and the T41 nlive
  consistency. 13 passed.
- Mutation test: lowering `T90_57_NLIVE_MIN_PRODUCTION` from 500 to 50 (which would make the
  smoke run look production-grade) failed 2 tests as intended; the file was restored
  byte-identically and 13/13 passed after restore.
